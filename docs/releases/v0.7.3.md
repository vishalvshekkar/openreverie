# v0.7.3

A repair release, and an unusually direct one. Almost everything here comes from one person actually
using v0.7.2 for a day and writing down what was wrong. Dreaming had never once run on a real memory
folder. The web session list did not appear until you reloaded the page. Tool calls showed a raw
function name while they ran and a line of raw JSON afterwards. The model wrote em dashes into
permanent memory files, in a project whose own writing rules forbid them.

None of that is new work. It is v0.7.0 and v0.7.1 not doing what their own documentation said they
did. That is worth stating plainly rather than dressing up as features.

## Dreaming actually runs now

Dreaming shipped in v0.7.0, is covered end to end by an automated suite against scripted fake
providers, and had never produced a dream on a real memory folder. Six separate defects sat between
"enabled = true" and a dream on disk. Each one alone was enough to stop it.

**The dreaming model defaulted to the reflection model.** The fallback read
`config.models.dreaming ?? config.models.reflection`. Dreaming runs a tool loop. Reflection never
does. So a perfectly reasonable config, one that named a reflection model which cannot call
functions, failed every dream with an HTTP 400 about function tools. The fallback is now
`config.models.chat`, the model already proven to run tool loops in every conversation.

**A failed dream left no trace at all.** No entry in `dreams/log.jsonl`, no `process.jsonl`, no
directory, nothing. The error was pushed onto an in-memory warnings list that no interface ever
read. That is the whole reason the problem above went unnoticed: the observable behaviour of a dream
that died on its first model call and a dream that was never due was identical, an empty folder. An
attempt now writes a durable record of its outcome and its reason, whether it succeeded or not.

**`reverie dream --force` could never work with the default settings.** Opening the engine fires the
`onStart` dream trigger without awaiting it. That background call took the dream lock, and the
command the person had just typed then found the lock held and declined with "another process is
already dreaming". One process, racing itself, with a message that sent you looking for a second
process that did not exist.

**`reverie web` never fired an early trigger.** The server opens the engine with maintenance
disabled, and the `onStart` trigger is gated behind that same flag, so the only web trigger was a
timer that first fires thirty minutes after start. Anyone starting the server, looking for a dream,
and stopping it never reached the first tick. The server now fires one attempt as soon as the engine
opens, and keeps the timer. Nothing new was needed to make that safe: the per-period attempt guard,
the lock file, and the recheck under the lock already prevent a double dream.

**The insight prompt pointed the model at evidence it could not resolve.** An insight has to name
real evidence: a document, a session, or a graph node. The prompt's only worked example showed a
document id, so the model tended to label everything that way, including ids that were sessions or
nodes. Those pointers resolved nowhere, every insight was dropped for unresolvable evidence, and the
dream aborted with nothing to write. The prompt now names all three id spaces, and resolution tries
each strategy for whatever id a pointer actually carries instead of trusting the field name. An id
that resolves nowhere is still rejected: this loosens how a pointer is read, never whether the thing
it points at has to exist.

**The narrative stage sent a temperature the model rejected.** Only visible once the others were
fixed and a dream got far enough to write its narrative. The dream narrative deliberately runs looser
than reflection prose, and newer reasoning models accept only their default temperature. This is
handled at the provider boundary, where knowledge about one provider's API belongs, rather than by
deleting a deliberate design choice from the dreaming code.

All six are fixed, and the proof is not a test fixture: a real dream now runs end to end on a real
memory folder, through seed selection, ten memory searches, insight generation with evidence that
resolves, the narrative, and the tone gate. The provider warning about the dropped temperature is
recorded in that dream's own `process.jsonl` rather than swallowed.

**Dreaming has an interface now.** The web Dreams tab reports whether dreaming is configured and
enabled, its cadence, which model it will actually use, how many reflected sessions you have against
the minimum, whether the current period is already covered or due, and why the last attempt did not
produce a dream. `reverie doctor` reports the same, and treats "enabled, due, and repeatedly
failing" as a failure rather than a silent skip.

## The conversation view

**The session list appeared only after a reload.** The mount effect started the auth bootstrap
without awaiting it and immediately asked for the session list. That request lost the race and came
back unauthorised, and a blanket catch threw the error away. On reload the cookie was already set, so
it worked, which is exactly what made it look like a display quirk rather than a race. The two calls
are now sequential, and a failed session list says so and offers a retry instead of failing silently.

**Speaker labels overlapped and rendered broken.** Every message carried an absolutely positioned
uppercase label in a fixed five rem box at a negative offset. The word "reverie" does not fit in that
box, so it overflowed into the rule beside it. The gutter is gone. Your messages sit in right aligned
bubbles, reverie's replies run as unlabelled prose at a normal reading measure, and screen readers
still get the attribution.

**Ended conversations showed a composer you could not use.** A text box, a send button, an end button
and a mode picker, all rendered and all disabled. An ended conversation now shows one line saying so.
The controls are absent, not greyed out.

**The composer was too small and the mode picker was in the wrong place.** The composer is now a
single rounded surface that starts several rows tall and grows to a limit, with a circular send arrow
inside it. Mode moved to the thread header as a pill showing just the name, opening a keyboard
navigable list with full descriptions. Sitting above the composer, it read as something you had to
choose on every message, when it is chosen once when the conversation starts.

## Tool calls say what they did

Fourteen tools, each with a running form and a finished form, and one canonical table so the terminal
and the browser cannot drift apart. "Remembering" while it happens, "Remembered" once it has.
The four listing tools used to share the single label "checking memory", which told you nothing about
which of the four had run.

Two behaviours changed alongside the wording.

**The chip no longer disappears when the reply arrives.** There is no tool completion event in the
stream, only a start, and the browser was clearing the indicator on the first token of the reply.
That moment is not arbitrary though: it is exactly when the tool is known to have finished. So the
chip flips from running to finished and stays, which is what the terminal already did with its
scrollback line.

**The result is a chip, not a wall of JSON.** A finished tool call is a small chip in its own accent,
visibly distinct from reverie's prose, that expands on click to show the raw payload. Reopening a past
conversation now renders the same chips a live one does. Tool results were always being stored
correctly, including for conversations held in the browser. They were rendered as raw JSON in the
faintest, smallest text on the page, and every tool call after the first in a round persisted as an
empty message under a "reverie" label, which is why it read as nothing being there.

## The atlas has colour

Every node type had the same near black fill, so the graph showed shape and nothing else. Each of the
seven types now has its own hue, and every one clears the 3:1 contrast floor against both the light
and the dark canvas. Node size still encodes degree, so hue and size separate different pairs of
types rather than competing. The legend swatches show the real colours.

Two bugs surfaced while doing it. Node labels had no colour set, so they inherited a hardcoded black
and were effectively invisible on the dark canvas. Fixing that broke hover labels, whose background
was also hardcoded, so those are themed now too. Colours also refresh when the system theme changes,
rather than staying stale until an unrelated rebuild.

## Em dashes and machine cadence

This project's writing rules forbid em dashes and the usual generated-text tics. That rule governed
the humans and the repository, and was never given to the model. It shows: memory files contain
sentences the model wrote with em dashes in them.

A prose voice rule now sits in the companion and firewall personas, in both reflection prompts, and
in both dreaming prompts. It governs sentence mechanics only, and says so explicitly, so that a mode
told to push back still pushes back and a mode told to stay out of the way still does.

Be clear about what this is. It is an instruction to a model, not a filter over its output. It should
meaningfully reduce em dashes and stacked clause cadence. It cannot guarantee their absence, and
nothing in this release inspects or rewrites what the model returns. A deterministic pass is recorded
in `BACKLOG.md` rather than claimed here.

## Settings say when they save

The settings page saved every field the moment you changed it and never said so, which leaves you
looking for a save button that does not exist. It now states the actual behaviour, including that a
`config.toml` change is read once at startup and therefore takes effect the next time you start
reverie, not while the current process keeps running.

## Documentation

The README claimed the package was not on npm and that `npm i -g openreverie` would not resolve. Both
were false from the moment v0.7.1 was published. The version line still said v0.7.0. Those are fixed,
and the account now distinguishes v0.7.1, which reached npm by hand, from v0.7.2, which the workflow
published.

## Known limits

Dreaming's machinery is tested and now demonstrably runs on a real memory folder. Whether a real
model's dreams are any good, whether an insight is worth surfacing, and whether the tone holds, still
has not had a human review pass. That gap is unchanged from v0.7.0 and is tracked in
`docs/dreaming.md`.

The prose voice rule is an instruction, not enforcement. See above.

The atlas palette separates palette-adjacent node types under simulated colour vision deficiency, not
all twenty-one pairs. Node size covers the pairs hue does not. Recorded in `BACKLOG.md` with the
measured numbers.
