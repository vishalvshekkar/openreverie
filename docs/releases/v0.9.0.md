# v0.9.0

v0.9.0 answers a single consolidated request from a hosted deployment built on this engine. Where
v0.8.0 made the engine runnable by a host without a local filesystem, native modules, a Node HTTP
server, or an ambient clock, this release makes it survivable by a host whose process evicts between
one message and the next.

Unlike v0.8.0, this one does change things a self-hosted person can see. Memory folders stay
compatible with v0.8.0 and need no migration, but two new files appear in them.

## A session can be resumed over its existing transcript

`AgentSession.resume` rebuilds a session's message history from the durable transcript instead of
minting a new session, and `LiveSessionRegistry.resume` puts it back in the live map. Without this, a
host that hibernates ends the person's conversation whenever its process sleeps.

Rebuilding is not a replay of transcript lines, and three things make it harder than it looks.

The in-memory history carries an inline time stamp on each user message that the transcript stores as
two separate fields. Re-deriving those stamps through the helper every other stored-transcript reader
uses would still change every user message, because that helper prints the stored offset where the
live path printed the person's timezone name. Resume checks the stored offset against the current
zone and reproduces the original bytes exactly when they agree, and falls back to the offset form,
reporting that it did, when they do not.

`setMode` appends a `/mode` line to the transcript and never to history, so those lines were never
part of what the model saw. They now carry a `historyOmitted` marker, true or absent, so no existing
transcript needs migrating and no reader written before it breaks.

An assistant tool-call line is appended before its tool is dispatched, so a process that dies in that
gap leaves a durable tool call that nothing answers. Those are dropped from the rebuilt history
wherever they sit, not only at the end: after one resume drops a trailing one, the conversation
continues and the next resume would find it in the middle. The transcript keeps every line; only the
rebuilt history omits them.

The assembled system prompt is now persisted per session, in `system-prompt.txt` beside the
transcript, and read back on resume. It is the start of the request prefix, so re-assembling it would
invalidate a provider's whole cached prefix however carefully the history below it was preserved.

`PublicSession` gains `resumable`. `readOnly` is unchanged and still means what it always meant, a
promise about this process.

## Ending a session no longer waits for its reflection

`LiveSessionRegistry.end` hands reflection to the same background seam the greeting and every turn
already used. A person ending a conversation in the browser now waits for their transcript to be
durable, not for one or two more model calls plus a rewrite for every arc and person that changed.
The terminal's own path is unchanged and still waits.

## Reflection has a durable attempt record

An append-only `sessions/log.jsonl`, modelled on the existing dream log, records that a reflection
attempt began and how it resolved. A reflection that failed partway used to leave the session looking
untouched, with nothing on disk saying it had ever been tried. Sessions now report not started, in
progress, reflected, skipped, or failed with a reason and a count. `summary.md` written last is still
the commit marker; this is a record alongside it.

`status: 'open'` now means only that no attempt has ever run. A session that has had reflection
attempted against it is never resumable, because a partial reflection may already have materialized
arcs, people or items from that transcript.

## Host-owned session lifetime

`LiveSessionRegistry` takes its idle timeout, sweep intervals and greeting timeout as options, and
its idle sweep and dream trigger can each be turned off outright rather than neutered with a
scheduler that never fires. The sweep walks an in-memory map, so a host whose process evicts between
messages can never sweep the sessions that most need it; saying that in the constructor is more
honest than implying it with a no-op.

`runMaintenance(now, { endSessions: false })` runs the rollup and index work without the
session-ending pass, for a host that has already ended what it meant to end.

`POST /api/v1/sessions` accepts `greet: false`, for a client whose person opens by typing rather than
being greeted.

## Search, and provider gateway headers

`GET /api/v1/search` exposes the same hybrid search the companion already reached through its own
tool, with a `limit` and deliberately no cursor, because a relevance ranking has no stable tuple a
later request could resume from.

`OpenAiConfig` accepts optional headers, merged so a supplied header can never displace
authentication. This is a privacy fix: a host routing through a provider gateway whose payload
logging is opt-out could not turn that logging off without it.

## Verification

`pnpm build`, `pnpm lint` and `pnpm exec tsc --noEmit` all exit 0, and the suite is 1,829 tests across
82 files. The self-hosted path was also driven by hand against the bundled binary and the Node server
with no provider configured: the memory folder is created, the read API answers, search returns a
defined 503 rather than an unhandled 500, ending a conversation returns in milliseconds with its
reflection still running, and that reflection's outcome is on disk afterwards rather than lost to the
shutdown.

## Known limits

Session resume has never run against a real model or a genuinely hibernating process. It is covered by
the automated suite and by a downstream consumer's own suite; the machinery is tested and the
behaviour in a live deployment is not.

Two capabilities in this release are reachable by code and not by a person. `GET /api/v1/search` has
no browser interface, so searching your own memory from the web client is still not something you can
do. Session resume has no HTTP route and the bundled Node server never resumes on its own, because
resume is driven by a host that keeps its own durable record of which session is live; a self-hosted
browser user cannot continue an interrupted conversation. Both are tracked in
[BACKLOG.md](../../BACKLOG.md).

Search cannot fall back to its keyword half when embeddings are unavailable: the lexical hits are
computed and then discarded when the embedding call fails, so a server with no provider configured
returns a 503 rather than partial results. Also tracked.
