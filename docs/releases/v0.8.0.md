# v0.8.0

v0.8.0 makes the engine usable by hosts that do not have a local filesystem, native modules, a
Node HTTP server, or an ambient clock and timezone. It does not change what the self-hosted CLI or
local web interface does, and memory folders remain byte-for-byte compatible with v0.7.3.

## Engine boundaries are explicit

Memory files now sit behind injected `FileStore` and `AppendOnlyStore` interfaces. SQLite can be
injected through `MemoryIndex.fromDatabase`, and `MemoryEngine.fromPaths` constructs an engine from
those host-owned dependencies. The clock and timezone are injected too. The local Node path still
uses the same stores, database, clock, and timezone behavior as before.

The provider interfaces now report optional token usage, and embedding rows record the model and
dimensions that produced them. This lets a host account for usage at the provider boundary and
prevents an index from silently comparing vectors with incompatible dimensions.

## A Web-standard server entry point

`@openreverie/server` now exports `createFetchApp`, a Web-standard
`(Request) => Promise<Response>` entry point. The existing `node:http` server is an adapter over
the same route core, so the `/api/v1` contract remains one implementation.

`createFetchApp` requires two host-owned choices:

- `canonicalOrigin`: an origin-only `http:` or `https:` URL used for exact Host and Origin checks.
- `writeOriginPolicy`: `required` for browser-only clients, or `allow-missing` for authenticated
  native and command-line clients that do not send `Origin`.

The origin is the public route origin, not the local listener address. This matters in Workers
development: a configured route can rewrite the incoming `Host` while leaving `Origin` alone.
Hosts must pass their configured public origin, rather than deriving it from a browser URL or a
loopback bind address.

The package barrel also defers its Node-only `createRequire` work until static assets are actually
needed, so importing the public server package no longer fails when `import.meta.url` is absent.
Bootstrap-cookie authentication is opt-in for Fetch hosts; self-hosted `createApp` keeps mounting
it exactly as before.

## Verification

The release candidate passed `pnpm build`, `pnpm lint`, and `pnpm test`: 81 test files and 1,635
tests. The automated suite cannot start a Workers runtime. A downstream integration verified the
public package entry point, the complete HTTP route core, authenticated streaming, registry
reconstruction, and the same flow through local Workers development.

## Known limits

The Node-specific `better-sqlite3` adapter remains importable at module scope. It works in the
tested host today because the dependency defers native loading until construction, but separating
that adapter remains tracked in [BACKLOG.md](../../BACKLOG.md). Bun and Deno have not been run.
