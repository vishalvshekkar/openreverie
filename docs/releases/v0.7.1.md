# v0.7.1

A packaging release. No behavior changes to the companion itself: the same features as v0.7.0, now
installable from npm in one command instead of requiring a clone and a build.

## Install

```
npm i -g openreverie
reverie setup
```

Or without installing anything: `npx openreverie`

`setup` runs a first-run wizard for your provider API key, your safety mode, and where your memory
folder lives. After that, `reverie` opens the terminal chat and `reverie web` serves the browser
interface.

## System requirements

- **Node 22 or newer.**
- **A platform `better-sqlite3` publishes a prebuilt binary for.** macOS, Linux and Windows on x64 or
  arm64 covers the large majority: installation downloads a binary and takes seconds. Off that grid
  (Alpine and musl, 32-bit ARM, or a Node major released before `better-sqlite3` has caught up), npm
  falls back to compiling from source, which needs Python and a C++ toolchain (Xcode Command Line
  Tools, `build-essential`, or Visual Studio Build Tools). It works, it is just slower and it is a
  surprise if nobody warned you.
- **An API key** for a model provider. OpenAI is the only adapter today.
- Disk for your memory folder, wherever you point it.

Not supported: browsers, serverless runtimes, Deno, Node below 22. Bun is untested.

## What the package contains

One runtime dependency, `better-sqlite3`. The four internal packages (`@openreverie/core`, `memory`,
`providers`, `server`) are bundled into the published binary and never appear in your `node_modules`.
The browser interface ships inside the package, so `reverie web` works immediately after a global
install rather than needing the repository.

Ten files, 398 kB packed, 1.8 MB unpacked. No source, no tests, no design documents, and nothing
resembling a memory folder.

## Fixes in this release

**Every command crashed in the bundled build, and only running it revealed that.** esbuild's ESM
output broke `gray-matter`'s CommonJS `require('fs')`, throwing "Dynamic require is not supported" at
module load, so even `reverie version` failed. Fixed by injecting a real `createRequire`-based
`require` into the bundle. A smoke test now runs the built binary as part of the build itself, so this
class of failure fails the build rather than reaching a user.

**The `reverie` command broke on every rebuild for anyone using `npm link`.** `tsc` writes
`dist/index.js` at mode 644, silently dropping the executable bit that `npm link` sets once. The
build now guarantees the bit, and it survives repeated builds.

**The web assets could not be found from an installed package.** The server resolved its static
directory by a path that only existed in a repository checkout. It now looks next to the running
bundle first.

**A test that passed or failed depending on how fast the machine was.** A status line test forced a
20 second timeout by advancing a fake clock in a loop bounded by iteration count rather than by the
work actually finishing. On a loaded CI runner the real setup never got far enough, the loop expired
having advanced nothing, and the test hung until the runner killed it. It now waits on
`vi.getTimerCount()`, an unambiguous signal that the timeout was registered, and fails with a message
naming what did not happen rather than a bare timeout.

## Publishing

Tagged releases publish to npm through GitHub Actions, which runs the full suite, the build and the
lint first and refuses to publish if any of them fail.

## Known limits, unchanged from v0.7.0

The honest caveats from the previous release all still stand, including the two worth repeating: the
commitments "ask once, then permanent silence" mechanism is not built (a two week bound stands in for
it), and no human has yet read a dream a real model wrote. The dreaming machinery is tested; the
dreaming output is not. See [v0.7.0](v0.7.0.md) for the full account.
