# v0.7.2

No change to the companion, the CLI, or anything a user runs. This release exists to prove the
automated publishing path works, and it is the first version published by it rather than by hand.

Saying that plainly matters more than padding it out: a release pipeline nobody has run is a release
pipeline nobody knows works, and the honest way to find out is to run it once on a version where
nothing else is at stake.

## What changed

**Publishing no longer uses a stored credential.** npm trusted publishing (OpenID Connect) now ties
the package to this repository and to `.github/workflows/publish.yml` specifically. The workflow mints
a short-lived token at run time and exchanges it with npm. There is no `NPM_TOKEN` secret, so there is
nothing to leak, rotate, or widen by accident.

The token wiring was removed rather than left in place as a fallback. A `NODE_AUTH_TOKEN` line kept
"just in case" would silently take precedence the moment anyone added the secret, quietly undoing the
guarantee that only a tagged run of that one file can publish.

**The package now requires two-factor authentication and disallows bypass tokens.** Trusted publishing
is exempt from that by design, so the two remaining ways to publish are a tagged run of the workflow,
or a human at an interactive terminal with a passkey. A leaked token is no longer one of them, because
there is no token.

**A defect fixed before it could fail a release.** Node 22 bundles npm 10.x, which has no OpenID
Connect support: the first automated publish would have tried to authenticate with a credential that
does not exist and failed. The workflow now upgrades npm before publishing, since trusted publishing
requires npm 11.5.1 or newer, and prints the resulting version so a future failure of this kind is
visible in the log rather than mysterious.

## Verifying this release

If the version you are reading about was published by the workflow, provenance is attached: npm shows
a "Built and signed on GitHub Actions" badge on the package page, linking the tarball to the exact
commit and workflow run that produced it. That is the visible outcome of `--provenance` plus the
`id-token` permission, and it is worth checking rather than assuming.

## Everything else

Unchanged from [v0.7.1](v0.7.1.md), including the install instructions, the system requirements, and
the honest limits carried forward from [v0.7.0](v0.7.0.md).
